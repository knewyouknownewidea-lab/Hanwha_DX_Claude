# 기존 프로젝트와 부품 구매 모듈 연결

## 추가 위치

대상 저장소는 `knewyouknownewidea-lab/Hanwha_DX_Claude`다. 기존 루트 구매 분석 앱과 `engine-dx`의 MAIN 01·MAIN 02·기술협의 API·데이터베이스·기존 모델을 유지하면서 새 부품 구매 모듈을 추가한다.

| 위치 | 역할 |
| --- | --- |
| `engine-dx/parts-viewer/` | 부품별 생성 소스·개발 소스·데이터 계약·출처·검증 자료 |
| `engine-dx/public/parts-viewer/` | 기존 웹 서버가 제공할 정적 배포 결과 |
| `engine-dx/app/Workspace.tsx` | 기존 메뉴에 **부품 구매** 링크 추가 |
| `/parts-viewer/index.html` | 추가 뷰어 진입 경로 |

루트 앱은 esbuild·React 기반이며, 기존 `engine-dx`는 Vinext·React Three Fiber·Three.js 기반이다. 새 부품 모듈의 정적 웹 배포 결과를 기존 `public` 아래에서 제공하므로 기존 MAIN 02의 뷰어·협의 기능을 교체할 필요가 없다. 원래의 메뉴와 주요 흐름은 유지한다.

기존 `engine-dx/package.json`의 dev/build 앞에 `node parts-viewer/scripts/integrate.mjs`를 연결했다. 이 스크립트는 부품 GLB·참고도·manifest를 재생성하고 정적 빌드를 `public/parts-viewer`에 복사한다. `npm run parts:build`로 독립 실행할 수도 있다. 생성 결과·vendor·GLB는 Git 소스에 중복 저장하지 않으며, GitHub의 부품별 소스와 생성 스크립트로 재생성한다. 다운로드 패키지와 비공개 시연에는 생성 파일을 포함한다.

## 기준 엔진 분리

기존 MAIN 02는 6G50ME-C9.6 시연 모델이다. 새 구매부품 모듈은 MAN B&W G95ME-C 계열의 공개 포스터와 공식 부품 외형 참고를 바탕으로 구조·연결 문맥을 설명하는 별도 개념 모델이다.

두 모델은 명칭이 비슷하더라도 세부 형상·보어·행정·체결·냉각·밸브 설계가 같다고 가정하지 않는다. 기존 모델의 500 mm 보어·2,500 mm 행정이나 기타 가정 치수를 G95 모듈에 가져오지 않는다. 새 모델의 6·7기통 반복 시연은 UI와 ID·공통 구조 재구성을 검증하는 개념 변형이며, 특정 제작 호기의 확인된 실제 엔진 사양을 뜻하지 않는다.

새 모듈은 **구조 설명용 모델 / 실제 제작 치수 아님**으로 표시한다. WinGD의 별도 계열 세부 구조도 MAN 계열 모델에 혼합하지 않는다.

## 연결은 명시적인 식별자만 사용

기존 모델 ID 예시는 `CYL_01_LINER`, 새 모듈 ID 예시는 `CYL01_LINER`다. 표기법이 유사하다는 이유로 자동 변환하거나 기존 협의·구매정보를 전송하지 않는다.

실제 연계가 필요할 때 다음 자료를 명시적으로 제공해야 한다.

1. 기존 ID와 새 `partId` 사이의 검토·승인된 매핑.
2. 실제 생산 호기의 `unitId`, 적용 엔진 형식·REV·기통 수.
3. 해당 `(unitId, partId)` 위치의 실제 품목번호·REV·공급업체 ID.
4. 원천 시스템이 확인한 필요량·가용재고·배정량·부족량·발주·일정·상태 사유·갱신일.
5. 컴플리트 구매와 개별 부품 구매를 구분하는 `parentPartId`·`procurementMode`·`bomIncluded` 정책.

새 모듈의 [데이터 계약](./data-contract.md)은 위 정보를 JSON으로 검증·표시하는 연결 경계다. 기존 기술협의 API에 데이터를 쓰거나 기존 협력업체·계약·발주·재고를 읽는 기능은 구현 범위에 포함되지 않는다. 실제 ERP·MES·PLM·SSO 또는 PDF 처리도 연결되어 있지 않다.

## 데이터의 초기 상태

새 모듈의 기본 모드는 **미등록**이다. 실제 수량·품목번호·업체·일정에 값이 없으면 `null`을 유지하고 화면에서 ‘미등록’으로 표시한다. 기존 기술협의의 가상 협력업체와 새 부품 모듈의 가상 협력사는 서로 다른 시연 자료이며 실제 공급관계를 뜻하지 않는다.

시연 모드에서만 `DEMO-` 호기와 ‘시연 협력사 A/B/C’, 가상의 수량·재고·발주·일정을 사용한다. 형상 참고에 사용한 업체를 실제 공급업체로 등록하지 않는다. 사용자 제공 실제 자료는 `dataKind:registered`와 `sourceDescription`을 명시해야 하며, 가상 ID를 실제 정보로 재분류하는 입력은 거부한다.

## 기존 기능 회귀 확인

기존 `engine-dx/checks/backend.mjs`는 인메모리 SQLite에서 실제 스키마와 API 업무 규칙을 검증한다. 새 부품 모듈 자체의 검증은 `parts-viewer/tests/`에 별도로 두며, 기존 기술협의 94개 객체·역할별 접근·협력사 범위·검토 게이트·회신·후속조치·원본 MAIN 01 해시·기존 GLB ID 검증을 대체하지 않는다.

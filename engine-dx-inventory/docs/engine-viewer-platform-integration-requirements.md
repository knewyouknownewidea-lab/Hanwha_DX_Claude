# 3D 엔진 뷰어 플랫폼(v0.3.3) 이식 요구사항

사용자가 추후 플랫폼에 3D 뷰어를 이식할 때 원하는 요구사항입니다. 설계 결정은 하지 않았고 미정으로 남깁니다. 아래 "연결점"은 `C:\Temp\engine-dx-repo\src\engine-dx` 현재 코드에서 확인한 사실입니다.

## 요구 1

> "A협력사 클릭 시 3D 모델링을 띄워주는 버튼을 한쪽에 추가."

**현재 engine-dx 구현과의 연결점**
- 3D 뷰어는 `app/Workspace.tsx`의 `Viewer`(`EngineViewer.tsx`, 동적 import)이며 props는 catalog, selected, onSelect, hidden, isolate, ghost, cutaway, explode, resetTick, focusTick, onReady입니다. 협력사 개념은 없습니다.
- 뷰어를 여는 버튼과 배치(모달, 별도 화면, 한쪽 패널)는 미정입니다.

**필요한 데이터**
- 협력사(SUP-xxx) 선택 상태를 뷰어에 넘기는 방법(미정).

## 요구 2

> "3D 모델링을 띄운다면, A협력사가 생산 납품하는 부품이 모델링 상에서 초록색으로 반짝임 추가. (이 경우에는 협력사 부품을 제외한 엔진의 나머지 부분이 반투명화)"

**현재 engine-dx 구현과의 연결점**
- `EngineViewer.tsx`에는 `ghost`(선택되지 않은 부품을 반투명 0.18로 표시)와 선택 부품 강조(주황)가 있어 "나머지 반투명"과 대응합니다.
- 선택은 단일 id(`selected: string|null`)만 지원합니다. 협력사 부품 여러 개를 동시에 강조하려면 확장이 필요합니다(미정).
- 초록색 반짝임(애니메이션 강조)은 현재 없습니다.
- 모델의 기본 부품 색(parts.json `color`)이 이미 초록 계열이라 강조색 구분은 미정입니다.

**필요한 데이터**
- 협력사별 납품 부품의 부품 유형(part_type_id) 목록. 현재 어디에도 없습니다(parts.json, inventory.json 모두 협력사 필드 없음).

## 요구 3

> "3D 모델링에서 다른 부품을 클릭 시 옆에 재고 수량만 띄워 주는 게 아닌, 해당 부품을 생산 중인 협력사 목록도 띄워주기, 그리고 그 협력사의 평가 등급, 납기 준수율 정도를 간략하게 보여주기"

**현재 engine-dx 구현과의 연결점**
- 부품 클릭 시 우측 재고 패널이 열리고 같은 부품 유형의 재고 합계와 세부 항목(도면번호·개정·재질·재고·안전재고·창고)을 보여 줍니다(`public/data/inventory.json`). 협력사 목록·평가 등급·납기 준수율 영역은 없습니다.
- 플랫폼 쪽 협력사 평가 등급·납기 준수율은 `metrics.ts`의 `supplierDelivery`, `evaluateSupplier`에 해당합니다(engine-dx 저장소 밖, 연결 방식 미정).

**필요한 데이터**
- 부품 유형(part_type_id) ↔ 협력사(SUP-xxx)·품목(ITM-xxx) 대응표(현재 없음, 새로 만들어야 하며 SAMPLE 가상 데이터여야 함).
- 협력사별 평가 등급, 납기 준수율(플랫폼 계산값 재사용 여부 미정).

## 공통 제약
- 이식하려면 three 계열 패키지(three, @react-three/fiber, @react-three/drei)가 필요한데, 플랫폼 규칙 5(새 npm 패키지 추가 금지, 필요하면 먼저 사용자에게 묻기)에 따라 승인이 필요합니다.
- 플랫폼의 협력사·품목 ID 체계(SUP-/ITM-)와 engine-dx 부품 ID 체계(CYL_xx_..., part_type_id)는 서로 대응되지 않습니다.

1. three 계열 패키지 추가를 승인할 것인가, 아니면 뷰어를 iframe·별도 빌드로 분리할 것인가?
2. 부품 유형(29종)과 플랫폼 품목(ITM-xxx)의 대응표는 누가, 어떤 기준으로 만드는가?
3. 협력사-부품 유형 대응은 SAMPLE 가상 데이터로 새로 만드는가?
4. 여러 부품 동시 강조(다중 선택)와 초록 반짝임을 `EngineViewer`에 추가하는가?
5. 협력사 평가 등급·납기 준수율은 플랫폼의 `evaluateSupplier`/`supplierDelivery` 값을 그대로 쓰는가?
6. 3D 뷰어를 여는 버튼은 협력사 화면의 어느 위치에, 어떤 형태(모달·패널·화면 전환)로 두는가?

## 구현 현황(독립 화면)
`C:\Temp\engine-dx-repo\src\engine-dx`의 독립 화면(5175 개발 서버, 헤드리스 Chromium)에서 아래까지 구현하고 확인했습니다. 가상 협력사 데이터는 `public/data/suppliers.json`(SAMPLE)입니다.

- **요구 1 (협력사 선택 시 3D 띄우는 버튼)**: 독립 화면에서는 3D가 항상 떠 있으므로 '버튼'을 3D 패널의 '협력사 강조' 선택 칸과, 재고 패널 협력사 행의 '이 협력사 부품 3D에서 강조' 버튼으로 대응했습니다. 플랫폼의 협력사 화면에서 클릭해 3D를 여는 버튼은 구현하지 않았고 이식 때 합니다(위치·형태 미정).
- **요구 2 (초록 반짝임 + 나머지 반투명)**: `EngineViewer`의 `highlightIds` 구현. 협력사 A 선택 시 담당 부품 42개(CONROD 6개 포함)가 초록 발광으로 반짝이고 나머지는 반투명 0.18입니다. 캔버스 0.0초/0.6초 캡처의 픽셀 차이로 반짝임을 수치 확인했고, `reduced-motion`에서는 고정 발광입니다. 사람 눈으로 본 느낌은 확인하지 못했습니다.
- **요구 3 (부품 클릭 시 생산 협력사·등급·납기 준수율)**: 부품 선택 시 오른쪽에 담당 협력사 목록(등급 '평가 A', 납기 준수율 %)을 표시합니다. 커넥팅로드는 협력사 A·B 두 곳이 나옵니다. 부품은 목록·검색 선택으로 확인했고, 마우스로 3D 부품을 직접 클릭하는 동작은 이번에 검증하지 못했습니다(3D 빈 곳 클릭 해제만 확인).

**이식 때 바꿀 것**: 뷰어와 효과(`EngineViewer`, `highlightIds`)는 그대로 가져가고 데이터만 바꿉니다. `suppliers.json`의 가상 협력사·등급·납기 준수율을 플랫폼의 SUP- 협력사와 평가 등급·납기 준수율로 교체하고, `supply`의 부품 유형(29종 part_type_id) ↔ 플랫폼 품목(ITM-) 대응표를 새로 만듭니다.

**미해결(사실)**: 이식 전 결정할 것 1~6은 그대로 미정입니다. 플랫폼 평가 값을 `evaluateSupplier`/`supplierDelivery`에서 가져올지, three 계열 패키지 승인, 유형↔품목 대응표 작성 주체는 정해지지 않았습니다. 초록 강조색은 기본 부품색(초록 계열)과 구분이 약한 부분이 있어 반투명 대비로 구분합니다. `pnpm build`와 8787 반영은 이번에 하지 않았습니다.

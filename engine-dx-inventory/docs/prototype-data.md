# 구매 시뮬레이션용 가상 데이터

사용자 요청에 따라 만든 프로토타입 데이터입니다. 실제 업체·계약·재고·제작 사양의 근거를 찾거나 추정하지 않았습니다. 부품 형상은 기존 구조 설명용 모델을 유지합니다.

`public/data/prototype-simulation.json`은 가상 6기통 호기 A와 7기통 호기 B, 가상 협력사 5곳, 가상 품목 24개, 선택 가능한 3D 객체 138개를 연결합니다. 협력사는 가상 한빛정밀, 가상 바다메탈, 가상 동해구조, 가상 누리유압, 가상 새론부품입니다. 이름·등급·납기 준수율·리드타임은 시연용 창작 값입니다.

## 첨부 표에 따른 관계

| 화면의 데이터 | JSON 관계 | 주요 열 |
|---|---|---|
| 재고 | `relations.stock` | 품번, 창고, 현재고, 안전재고, 기준일, 부적합 보류량, 합격 가용량 |
| 3D 부품 매핑 | `relations.modelMappings` | 생산 호기, partId, 모델 부품 이름, 품번, 도면번호, REV |
| 품목 | `relations.items` | 품번, 품명, 가상 규격, 단위 |
| 협력사 | `suppliers` 및 `supply` | 협력사 ID·명칭, 취급 품번, 리드타임, 호기별 실제 강조할 partId |
| 발주 및 입고 | `relations.purchaseOrders` | 발주번호, 수량, 필요일, 약정일, 입고 예정일, 확정 여부, 입고 상태 |
| 입고검사 | `relations.inspections` | LOT, 품번, 발주번호, 검사 수량, 부적합 수량, 검사일 |
| 생산계획 및 BOM | `relations.productionPlans`, `relations.bom` | 엔진 번호, 조립일, 기통 수, 품번별 소요량, BOM 포함 여부 |

최상위 `supply`와 `inventory.types`는 기존 부품 뷰어와 호환되는 화면용 자료입니다. 동일 호기의 각 위치를 독립된 공급 행으로 유지합니다. 두 호기의 같은 `CYL01_LINER`는 각각 다른 품번·REV·협력사를 갖습니다. 협력사의 취급 품번 목록으로 3D 강조를 추론하지 않습니다.

## 단순화한 계산

현재고는 창고에 있는 검사 보류품도 포함한 가상 수량입니다. **합격 가용량 = 현재고 − 부적합 보류량**으로 계산합니다. 부적합은 검사 관계에서 한 번만 차감합니다. 안전재고는 경고 기준이며 가용량에서 자동 차감하지 않습니다.

가용 수량은 같은 품번의 구매 위치에 순서대로 1개씩 배정합니다. 동일 재고를 여러 위치에 중복 배정하지 않습니다. 이 순서는 화면 작동을 보여주기 위한 가정이며 실제 생산 우선순위 계산이 아닙니다. `available`은 선택 위치에 제공할 수 있는 합격 수량, `allocated`는 해당 위치에 배정한 수량입니다. 현재고와 유형 합계는 따로 표시합니다.

초록은 가용재고 배정 완료, 노랑은 입고 예정 또는 일정 확인 필요, 빨강은 추가 확보 대책 없는 부족입니다. 지연 시나리오의 노랑은 해결 완료를 뜻하지 않습니다. 입고 예정량만으로 초록으로 바꾸지 않습니다.

배기밸브는 두 호기 모두 조립체 구매입니다. 하위 하우징·스핀들·시트는 매핑과 개별 ID를 유지하고 BOM 소요량은 0으로 제외합니다. MBS는 베드플레이트의 통합 영역이며 별도 구매로 집계하지 않습니다. 쉘과 실린더 프레임도 이번 범위에서는 연결 문맥으로 제외합니다. 이 객체들의 품번·도면번호는 연결표 확인을 위한 가상 식별자이며 독립 발주를 의미하지 않습니다. 독립 구매 대상이 아닌 객체의 자재 상태는 회색(`unknown`)으로 두고 사유에 BOM 제외 이유를 표시합니다. 공급 강조와 객체 선택은 계속 작동합니다.

## 시나리오

1. **기본 생산계획:** 확보·입고 예정·미확보가 섞입니다. A호기 `CYL05_LINER`는 입고 예정이고 `CYL06_LINER`는 미확보입니다.
2. **예정 물량 입고:** 열린 발주를 입고·검사 합격 처리하고 재배정합니다. A호기 `CYL05_LINER`는 확보로 바뀝니다. 발주 없는 `CYL06_LINER`는 미확보로 남습니다.
3. **협력사 납기 지연:** 열린 발주 예정일을 14일 늦추고 확정 여부를 해제합니다. A호기 라이너는 11월 5일에서 11월 19일로 바뀌며 필요일 11월 10일을 넘깁니다.
4. **입고검사 부적합:** 각 호기의 커버 2개를 보류합니다. 현재고는 유지하고 가용재고만 감소합니다. A호기 5·6번 커버는 미확보로 바뀝니다.

모든 시나리오는 원본 `simulationSeed`에서 시작하므로 전환·반복해도 입고나 부적합이 누적되지 않습니다. 입고 시나리오는 기준일 다음 날의 가상 이벤트입니다. 실제 ERP, 발주 승인, 입고 확정 API는 호출하지 않습니다.

## 재생성 및 검증

```sh
node scripts/generate-simulation.mjs
node checks/simulation.mjs
```

생성기는 기존 3D 모델 메타데이터에서 ID를 읽으며 메시를 변형하지 않습니다. 검사는 관계 키, 전체 객체 매핑, 호기별 공급사 강조, 재고 중복 배정 방지, BOM 중복 제외, 시나리오 변화를 검증합니다. 실제 수급 최적화·금액·부분 입고 분할·호기간 공용재고 최적 배분은 구현 범위 밖입니다.
